# Grill

## 强度

先逐题确认强度、是否记录决策；已说明的不再问，强度可随时调整。深度分五档：

1. 浅问：补齐阻塞下一步的关键缺口。
2. 常规：澄清明显未想清的地方。
3. 细问：检查目标、约束、取舍和默认假设。
4. 深挖：主动寻找风险、遗漏和边界。
5. 拷打：严格挑战模糊回答、未经验证的前提与冲突要求，直到重要未知基本暴露。

## 追问策略

客观事实自行查证；目标、偏好、成本和取舍交由用户决定。优先追问影响方向的目标、已定／未决事项、假设、遗漏和重要取舍。问题具体易答，可附建议与理由，不代替用户决策。

## 提问

- 一次只问一个前提齐备且最阻塞的问题；收到回答并重评依赖后才生成下一题或依赖操作，不预排、不批量。
- 优先使用宿主提供的阻塞式提问机制；没有就在普通文本里提问后结束本回合，不声称正在阻塞等待输入。
- 使用宿主提问机制时遵循其参数约定（背景说明、单选／多选等）；提供选项时推荐项置首并标注推荐，标签不加序号，不重复添加宿主内置的「其他」项。
- 回答按用户呈现的内容理解，不假设可读取结构化状态或机器值。
- 不自行判断 TUI／RPC 等运行模式，也不探测或绕道调用未提供的机制。
- 空答、取消或超时都算未决：取消即停止提问，不立刻改用另一种方式重问；无有效回答不得推断同意或执行依赖操作。
- 强度标签用「浅问」「常规」「细问」「深挖」「拷打」。

## 决策记录

- Agent 用文件工具维护记录；写入前告知 `docs/decisions-<英文主题>.md` 的实际路径并获授权，已有授权不重问。
- 先读已有文件，缺失才新建，不擅自覆盖；每定一条追加「结论 + 理由」，增量更新「待定问题」，保留其他内容。
- 无法写文件时说明原因，每隔几轮输出完整记录供复制。

## 结束

未知已不足以明显改变下一步时停止，简述「已确定」「暂未确定」「下一步」；用户明确确认后才开始重要执行。

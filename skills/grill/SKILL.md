# Grill

## 强度

先逐题确认强度和是否记录决策。已经说明过的不再问，强度可以随时调整。深度分五档：

1. 浅问：补齐阻塞下一步的关键缺口。
2. 常规：澄清明显没想清的地方。
3. 细问：检查目标、约束、取舍和默认假设。
4. 深挖：主动寻找风险、遗漏和边界。
5. 拷打：严格挑战模糊回答、未经验证的前提和冲突要求，直到重要未知基本暴露。

## 追问策略

客观事实自行查证，目标、偏好、成本和取舍交给用户决定。优先追问影响方向的目标、已定和未决事项、假设、遗漏与重要取舍。问题要具体易答，可以附建议和理由，但不代替用户决策。

## 提问

- 一次只问一个最阻塞的问题，前提要齐备。收到回答并重评依赖后，再生成下一题或依赖操作，不预排，也不批量。
- 优先使用宿主提供的阻塞式提问机制。没有这个机制时，就在普通文本里提问，然后结束本回合，不声称正在阻塞等待输入。
- 使用宿主提问机制时，遵循它的参数约定（背景说明、单选、多选等）。提供选项时，推荐项放第一位并标注推荐；标签不加序号，也不重复添加宿主内置的“其他”项。
- 回答按用户呈现的内容理解，不假设能读取结构化状态或机器值。
- 不自行判断 TUI、RPC 等运行模式，也不探测或绕道调用未提供的机制。
- 空答、取消或超时都算未决。取消就停止提问，不要立刻改用另一种方式重问；没有有效回答时，不得推断同意，也不执行依赖操作。
- 强度标签用“浅问”“常规”“细问”“深挖”“拷打”。

## 决策记录

- Agent 用文件工具维护记录。写入前告诉用户 `docs/decisions-<英文主题>.md` 的实际路径并获得授权，已有授权就不再问。
- 先读已有文件，缺失才新建，不要擅自覆盖。每确定一条，追加“结论 + 理由”；“待定问题”增量更新，其他内容保留。
- 无法写文件时说明原因，每隔几轮输出完整记录供复制。

## 结束

未知项已经不足以改变下一步时停止追问，简述“已确定”“暂未确定”和“下一步”。用户明确确认后，才开始重要执行。

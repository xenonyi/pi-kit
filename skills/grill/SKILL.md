# Grill

## 强度

先逐题确认强度、是否记录决策；已说明的不再问，强度可随时调整。深度分五档：

1. 浅问：补齐阻塞下一步的关键缺口。
2. 常规：澄清明显未想清的地方。
3. 细问：检查目标、约束、取舍和默认假设。
4. 深挖：主动寻找风险、遗漏和边界。
5. 拷打：严格挑战模糊回答、未经验证的前提与冲突要求，直到重要未知基本暴露。

## 追问策略

客观事实自行查证；目标、偏好、成本和取舍交由用户决定。优先追问影响方向的目标、已定／未决事项、假设、遗漏和重要取舍。问题具体易答，可附建议与理由，不代替用户决策。

## Pi 提问

- 以当前可用工具为准，不自行判断 TUI／RPC 等运行模式。仅当 `ask_user_question` 可用且用户未禁止调用时，**直接、逐题**调用（`model-only`、`sequential`），不用 codemode、批量或并行。
- 工具未提供、不可用或被用户禁用时，不搜索、激活或绕道调用；改用普通文本提出一个最阻塞的问题并结束本回合，不声称正在阻塞等待输入。
- 无论采用哪种方式，先问前提齐备且最阻塞的问题；收到回答并重评依赖后才生成下一题或依赖操作，不预排。
- 使用工具时，`question` 仅放问题，背景／建议／理由放 `details`。单选用 `options`，多选加 `multiSelect: true`，开放题省略 `options`。`label` 不加列表序号；强度标签用「浅问」「常规」「细问」「深挖」「拷打」。推荐项置首，标签末尾加 `(Recommended)`；不重复添加内置 Other。
- 按工具返回的 `content` 文本理解回答，不假设可读取结果 `details` 的结构化状态或机器值。
- 空答（即使工具标为 `answered`）仍未决；取消即停止提问，不立即换文本重问。无有效回答不得推断同意或执行依赖操作。

## 决策记录

- Agent 用文件工具维护记录；写入前告知 `docs/decisions-<英文主题>.md` 的实际路径并获授权，已有授权不重问。
- 先读已有文件，缺失才新建，不擅自覆盖；每定一条追加「结论 + 理由」，增量更新「待定问题」，保留其他内容。
- 无法写文件时说明原因，每隔几轮输出完整记录供复制。

## 结束

未知已不足以明显改变下一步时停止，简述「已确定」「暂未确定」「下一步」；用户明确确认后才开始重要执行。

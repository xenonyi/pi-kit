# 外部查证

## 1. 确定证据缺口

从已有上下文、用户材料和相关本地代码中确定缺口，只检索尚未回答的问题。固定待查对象、目标版本、环境和时间范围；查“当前”或“最新”时，明确截至日期。

查询只带公开名称、脱敏错误和必要的环境信息。密钥、私有代码和个人信息留在本地。

完成条件：每个待答问题都有现有证据或具体检索目标。现有材料足够时直接作答。

## 2. 找到原始来源

按下表选入口，调用前读对应说明：

| 需要的资料 | 首选入口 |
| --- | --- |
| 库、框架、SDK、CLI 的 API、配置、迁移或排错文档 | [context7](references/tools.md#context7) |
| 公开 GitHub 仓库的模块关系与实现位置 | [deepwiki](references/tools.md#deepwiki) |
| 其他公开网页事实，或已有 URL 的正文 | [exa](references/tools.md#exa) |

首次使用某服务前，用 `tool_search` 发现工具，在 `codemode` 中按当前工具声明调用。返回后先检查 `isError`；调用失败、需要解析返回体或处理长文时，读 [结果处理](references/results.md)。

搜索摘要和生成式回答用于定位原文。沿引用找到官方文档、发布说明、上游源码或规范等一手资料；二手来源作为补充，标明其身份。

完成条件：每个检索目标都有可核验的原文位置，或已记录无法继续的原因。

## 3. 逐项核验

- 读到能支撑结论的正文段落，同时核对前置条件和例外。
- 先核对版本、环境和日期，再比较来源权威性。版本差异分别陈述；同一条件下仍有冲突，保留各方依据并说明取舍。
- 仓库的实际行为由本地代码确认，上游文档用于说明其约定。
- 版本号、日期、数值、单位、价格和 API 签名按原文保留。示例只支持它覆盖的条件。
- 将“搜不到”和“原文未读全”记为证据不足；基于资料推导的判断标为推断。

完成条件：每项待查的外部结论都有正文支持，或明确标为冲突、推断或证据不足。

## 4. 带来源交付

先给结论，再把来源放在对应事实旁，格式为 `来源：[标题](URL)（日期或版本）`。时效性事实另附核验日期。

同一事实留一个最直接的来源，存在冲突时并列引用。链接取自实际读取的结果；日期或版本缺失时省略对应项。

原文摘引用引号或引用块标明，只留支撑结论的必要短句或代码行，省略处明确标出。

完成条件：逐项回应全部待答问题；每项外部事实可追到已读正文，未决项写明影响和继续查证所需条件。

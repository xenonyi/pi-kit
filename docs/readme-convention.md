# README 编写规范

本仓库有两类 README：根 `README.md`（仓库索引）与 `extensions/<name>/README.md`（单个扩展）。

## 通用规则

- 中文正文；代码、命令、路径、工具名、字段名保持原语言
- `#` 标题后紧跟一句话定位：做什么 + 解决什么问题 + 关键前提（例如「仅在 TUI 会话声明」）
- 章节名与顺序固定；没有内容的章节整节省略，不写「无」「待补」
- 表格分隔行统一写 `| --- |`；参数表列为「参数 / 说明」，键表列为「键 / 默认 / 说明」
- 行内代码用于命令、路径、字段、工具名；代码块标语言（`sh` / `json` / `md` / `text`）
- 只写代码里能查到的事实；没验证过的行为不写
- 相对链接必须指向仓库内真实文件
- 不复制会随代码漂移的全量细节：写关键项 + 指回源码或 `docs/`
- 不写「限制」「目录」两节

## 扩展 README 骨架

```text
# <扩展名>
一句话定位

## 使用            # 注册的工具 / 命令、参数表、交互按键
## 配置            # 读取顺序 + JSON 示例 + 键表（无配置则省略）
## 行为            # 关键语义、边界、触发条件、失败时的表现
## 来源            # 派生自上游时写清出处与许可（原创则省略）
```

- 「使用」「配置」「行为」三节的相对顺序不可变
- 扩展专属章节（如 `## 内置服务器`、`## 安全`、`## 片段格式`、`## 条件`）插在「使用」之后或「行为」之后，不打断上述三节
- 工具与命令在首次出现处写全名：`hash_edit`、`/rules doctor`
- 失败路径必须写清结果：报错、跳过，还是退回原生渲染

## 根 README 骨架

1. 标题 + 一句话定位
2. `## 快速开始`：安装与类型检查命令
3. `## 扩展`：扩展表（扩展 / 说明 / 文档链接）
4. 其它内容目录（如 `## 技能`、`## 规则片段`）
5. `## 开发`：仓库级约定，链接到 `AGENTS.md` 与本文档

- [ ] 表格分隔行是 `| --- |`
